# GitHub identity and private repository access

The HTTP flow starts with `GET /auth/github/login` and returns to `GET /auth/github/callback`. A random browser binding cookie and one-use state bind the callback to the browser that started it; PKCE binds the authorization code. GitHub `/user` supplies the stable numeric account ID. The first verified login creates one local user for that ID, or returns its existing user. It never merges accounts by email. The required email column holds `github-<id>@ariadne.invalid`, an internal placeholder that is never returned by the identity API; the password column holds an `!oauth-disabled:` marker rather than a usable password hash. Any future password-login verifier must reject that marker. Login rotates the server-side session ID. `POST /auth/github/private` links private repository access to the current session, and the callback rejects a different local user. Both flows request expiring credentials with `offline_access`. The private flow also requests GitHub's broad `repo` scope; GitHub OAuth does not offer a read-only private-code scope. The UI should explain this before connection. No user token is requested or pasted into Ariadne.

Configuration: set `ARIADNE_DATABASE_URL`, `ARIADNE_GITHUB_CLIENT_ID`, `ARIADNE_GITHUB_CLIENT_SECRET`, `ARIADNE_GITHUB_REDIRECT_URI` (HTTPS URL ending in `/auth/github/callback`), and `ARIADNE_OAUTH_FERNET_KEYS` (one or more comma-separated Fernet keys; first encrypts, remaining keys permit rotation). Keep secrets in a secret manager, outside Git and logs. `build_identity_http_from_env()` validates all settings and required tables, opens an autocommit PostgreSQL connection, and returns the object that the app places in `app.state.identity_http`; close it at shutdown. Mount `create_identity_router()` and use `require_session_user` as the FastAPI dependency on every protected API route. With missing configuration or tables, the manager is not installed and auth/API routes return 503 `configuration_unavailable`; there is no header-based user fallback. The OAuth app and HTTPS callback must be registered separately by the operator. This repository does not create or publish an OAuth app.

On a new PostgreSQL database, call `app.database.apply_schema(connection)` first, then `app.security.identity.apply_identity_schema(connection)`, and commit the schema transaction. Both must run before serving OAuth requests. `PostgresIdentityStore` requires an autocommit psycopg connection so one-use state creation and atomic `DELETE ... RETURNING` consumption are durable across workers. Run the additive identity schema step on existing installations too; there is no implicit table creation at request time. A missing table or database connection is a deployment error, not a successful sign-in.

Authorization uses a 10-minute random state stored only as a SHA-256 digest, a PKCE S256 verifier encrypted at rest, and a single atomic state consumption before code exchange. Anonymous login additionally binds the state to a random HttpOnly browser cookie. Wrong browser, wrong local user, wrong purpose, expired state and replay fail. After exchange, the service stores access and optional refresh credentials only as Fernet ciphertext. A conflicting local-to-GitHub link fails. Expiring tokens refresh when possible; expired or revoked grants require reconnection. Each private read rechecks GitHub identity and GitHub itself authorizes the metadata or SHA-pinned blob request. A revoked token or lost repository permission fails closed. The private reader accepts canonical GitHub URLs, rejects redirects, applies the same file and size limits as the public reader, and never runs repository code.

Sessions are opaque random cookies; PostgreSQL stores only their digests and allows one active session per local user. Cookies use `Secure`, `HttpOnly`, `SameSite=Lax`, `Path=/`, and the `__Host-` prefix. Sessions expire after eight hours; new login/private authorization rotates the ID and `POST /auth/logout` revokes it. `GET /auth/me` returns only `user_id` and a CSRF value. Unsafe protected requests, including private authorization and logout, require `X-Ariadne-CSRF` with that value. A stolen still-active cookie remains usable until rotation, logout or expiry; HTTPS and browser protections are required. `GitHubPrivateService.fetch_repository(local_user_id, github_url)` returns an owner-bound snapshot with immutable commit, tree and blob SHAs. `fetch_file(local_user_id, snapshot, file)` rechecks the owner, live GitHub permission, source repository ID and current commit before reading a selected blob. Blob bytes must match the tree's size and Git SHA. Callers must keep snapshots and derived analyses scoped to the same local user and reauthorize before serving any cached private content. Local fixture and PostgreSQL tests do not prove a deployed OAuth app or live sign-in.

`GitHubPrivateService.document_files(local_user_id, snapshot)` and `fetch_document_file(local_user_id, snapshot, file)` use the public reader's safe README/docs/manifest selection, file/count/total-byte limits, Git blob hash validation and `.env` template redaction. They also check owner, live private token, GitHub repository ID and current commit on every call. The document result is untrusted repository data, never an instruction to execute. Redacted `.env` templates must not be passed into the RAG index because their returned text intentionally differs from the source blob. For private document indexing, pass raw non-env document texts with the same `PrivateRepositorySnapshot` through `private_document_snapshot=`; T20's index requires its owner and exact repository snapshot to match the live private scope. The API caller must preserve this wrapper from the reader through indexing.

`app.services.github_private.scope.LiveRepositoryScopeResolver(Store(connection), oauth_service)` is the callable authorization adapter for T20's `QdrantIndex` and T21's answer recheck. Give the T02 `Store` an autocommit PostgreSQL connection so each owner check sees a fresh committed state. Call the resolver only with a trusted session user ID and a local repository UUID. It first checks the T02 owner-scoped row, then reads GitHub metadata and the current default-branch commit on every call. A private repository additionally requires the owner's current OAuth identity and GitHub repository permission. The returned `AuthorizedScope` has the local repository UUID, the live GitHub repository ID, current SHA and visibility. Wrong owner, missing token and lost permission return no scope; GitHub or database outages raise a sanitized error, so cached private results cannot be served. The resolver's repeated remote checks are intentional and can be rate-limited; callers should treat an unavailable check as denied for content delivery, not reuse an earlier scope.
